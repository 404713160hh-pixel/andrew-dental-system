# 安德鲁牙科患者小程序

微信原生小程序，TypeScript 严格模式、WXML、WXSS、官方 `wx.request` 与本地存储 API。提供首页、门诊与医生介绍、治疗参考价资料和本人预约闭环；没有支付、处方、病历、正式消息或家庭成员代约入口。

## 本地构建和导入

在仓库根目录执行：

```powershell
npm install
npm run typecheck -w @andrew/miniprogram
npm run build -w @andrew/miniprogram
npm run test -w @andrew/miniprogram
```

先按照根 README 启动 PostgreSQL 和新后端。小程序默认连接 `http://127.0.0.1:3310/api/v1`，与 Vue 工作台共用同一后端、同一 PostgreSQL。

打开微信开发者工具，选择导入 **本目录 `miniprogram`**，不要导入 `src`、`dist` 或旧版 `public`。根 `project.config.json` 的 `miniprogramRoot` 为 `dist/`。`npm run build` 将 TypeScript 编译为原生 CommonJS，并复制 WXML、WXSS 和 JSON 到 `dist`。修改源码后重新构建；`watch` 只监听 TypeScript，修改 WXML/WXSS/JSON 后仍需运行完整 build。

`src/contracts.d.ts` 在构建/检查时从仓库 `shared/src/index.ts` 自动生成，仅用于编译，不手工维护另一份 DTO；`dist` 和该声明文件不入库。所有网络响应来自真实 API，没有客户端硬编码的门诊、医生、服务、号源或成功预约数据。

## AppID、地址与微信配置

- 未配置真实 AppID 时，`project.config.json` 使用 `touristappid` 方便本地工程导入。不同版本开发者工具的游客能力可能有限；需要登录开发者工具或真机预览时，请替换为自己的测试/正式小程序 AppID。
- 唯一 API 地址位于 `src/config.ts`。模拟器可使用 `127.0.0.1`；真机的 `127.0.0.1` 是手机本身，应改为电脑的局域网 IP，并确保手机和电脑在同一网络、后端可由局域网访问，再重新 build。
- 本地项目 `urlCheck:false`。在开发者工具“详情→本地设置”确认已关闭合法域名、TLS 版本及 HTTPS 证书校验，仅用于开发调试。
- 发布前必须把 API 改为 HTTPS，使用有效证书，并在微信公众平台配置 `request` 合法域名；恢复域名校验。数据库端口不供小程序直接访问。
- 小程序不保存数据库连接串、AppSecret 或服务器密钥。AppID 可见，AppSecret 只能放后端环境变量。
- 当前没有微信授权登录联调。账号密码由后端验证，开发演示入口由 `GET /auth/config` 决定是否显示，账号列表动态取得，`POST /auth/demo` 仍由后端签发真实会话；正式部署默认关闭。没有把 `wx.login` 的假 code 当作已验证身份。

| `pages/profile` | 本人身份核对、联系方式、逐项过敏声明、版本更新、退出 | UC-01 |
| `pages/booking` | 门诊/服务/日期/医生筛选、资格展示、服务器号源查询、建立占位 | UC-02/03/04 的查询结果、UC-05 |

`app.json` 当前登记 10 页。患者端只使用已发布资源，不承担医生档案、资格、目录、班次维护；这些由 Vue 员工端和后端权限处理。未知过敏 `unknown`、声明无已知过敏 `none_reported`、已知过敏 `known` 分开显示；已知过敏按行填写多项。当前只支持账号本人，手机号不是患者唯一身份，也不能凭手机号认领其他患者。

## 演示资料、医生与价格边界

本地合成数据通过根目录的 `npm run db:demo` 增量建立。该命令仅用于开发/测试，生产环境禁止执行。医生、患者和联系方式均为合成资料：医生公开接口返回 `isDemo`、`bio`、`focusAreas` 和未来已发布排班门诊 `clinicIds`；本人资料返回只读 `isDemo`。小程序根据实际标识展示“虚构医生/虚构患者”，不凭姓名推断身份，不出现真实医院任职、名医背书或虚构执照编号。头像为 CSS 示意形象，首页牙齿插图为仓库本地 SVG。

医生详情仅将医生 `serviceIds` 与门诊服务 `clinicIds` 交集列为可选咨询；点击后携带医生、门诊、服务 ID 进入预约页。预约页重新取得匹配医生并恢复预选，实际号源仍由后端查询。指定医生或服务不匹配时明确提示，不能静默替换。仅携带资料关联服务的入口，会先定位实际开展该服务的开放门诊。

`GET /treatment-references` 提供只读资料，每项含类别、名称、整数分价格上下限、单位、年份、来源说明、项目说明及可空的 `bookingServiceId`。本次参考年份为 2026，来源明确为“用户提供的价格资料（未独立核验）”。页面逐项展示来源与单位，并说明这些资料不能作为本门诊报价。页面类别、医生、患者及价格数值全部来自 API，不在小程序写死。

种植、正畸等疗程资料价与本次咨询预约费分开：资料页的“预约相关咨询”只传 `bookingServiceId`，不将治疗上下限或资料单价带入占位/确认。服务页及确认页展示服务自己的 `priceCents` 参考费，后续治疗、另需检查和材料以面诊方案为准；本次预约不执行支付。价格先以整数分校验，再格式化到小数显示，避免把 `39.9` 显示为浮点长尾。

个人资料保存时显式剥除 `id`、`rowVersion` 和只读 `isDemo`，仅发送可编辑档案与预期版本。患者端只读取本人档案与本人预约，不开放患者目录、其他患者检索或员工入口。预约确认使用已取得的本人档案和公开医生标识；列表与详情使用预约返回的 `patientIsDemo`、`doctorIsDemo`。这些仅为展示元数据，不改变命令幂等、跨账号隔离和未知结果恢复规则。

## API 和一致性

统一前缀 `/api/v1`，成功包 `{ data, requestId }`，失败包 `{ error: { code, message }, requestId }`。会话采用后端签发的 Bearer token。客户端只发送选择、版本和确认声明，最终可预约性由服务器校验。

- 公共目录：`GET /clinics`、`GET /services?clinicId`、`GET /doctors?clinicId&serviceId`、`GET /treatment-references`、`GET /booking-policy`。
- 身份/资料：`GET /auth/config`、`POST /auth/demo`、`POST /auth/login`、`POST /auth/register`、`GET /me`、`GET/PUT /patients/me`、`POST /auth/logout`。
- 查询与占位：`GET /booking-slots`、`POST /booking-holds`。
- 确认和变更：`POST /appointments/confirm`、`POST /appointments/{id}/changes`。
- 本人记录：`GET /appointments`、`GET /appointments/{id}`。
- 写入结果核对：`GET /commands/{key}`。

选择时段后先创建短时占位，并显示服务器返回的 `expiresAt`；倒计时仅为客户端提示，服务器截止时间才是最终依据。占位不是正式预约，成功反馈仅在服务器确认事务提交后展示。保留时间、取消提前量和其他预约规则全部由 API 返回，没有在页面写死业务数值。

确认、取消、改期在发送前保存原请求、原 key 和所属账号。网络失败或不完整的成功响应显示“结果待确认”；核对和重试继续使用原 key。`not_found` 不被当作原请求永远不会成功的证明，不生成新 key 自动重占。重开页面后，可从“我的预约”恢复。不同账号的待确认操作分别存放，互不可见且不会覆盖；同一原账号重新登录后继续核对。

改期选择新时段时原预约保持有效，因此不提供与原有效预约重叠的号源。新的资源分配和原预约变更由后端原子事务处理。取消或改期失败不会在本地伪造成功，也不会先从页面移除原记录。预约、到诊和诊疗完成不混为一类状态。

## 微信开发者工具人工验收

以下是微信开发者工具与真机的独立验收步骤，实际执行情况以最新 QA 记录为准；Node 客户端测试不能代替这些步骤：

1. 启动后端和 PostgreSQL。在工具中导入本目录并确认 API 地址与合法域名开发设置。
2. 打开首页，核对门诊/服务与 Vue 工作台一致；查看医生、按门诊筛选、进入详情并指定医生预约，确认演示标识、资格说明与服务匹配；查看价格资料的类别、搜索、单位、来源与咨询跳转。断开后端再重试，确认错误状态与重新加载按钮有效，没有静态成功数据。
3. 登录服务端提供的测试患者，或注册一个完整资料账号。检查个人资料仅为本人，修改联系方式、已知/无已知/未知过敏后重新进入，核对保存和版本行为。
4. 在 Vue 员工端新增合格医生班次。小程序选择同一门诊、服务和日期查询，确认号源同步出现；指定医生时显示资格。
5. 选择时段，核对占位倒计时、本人和联系方式、过敏提示、取消提前量。未勾选核对项不能确认；占位到期不能显示成功。
6. 正式确认后核对唯一编号、我的预约详情，以及 Vue 中同一笔预约。通过 PostgreSQL 或后端集成测试核实数据，不仅看页面提示。
7. 使用第二患者账号竞争同一资源，验证只有一人成功；客户端错误不能显示另一患者信息。
8. 模拟提交后断网或服务响应中断。关闭并重新打开页面，“我的预约”仍显示待确认；恢复网络核对或重试原操作，确认只产生一笔预约。
9. 在允许取消的时间内填写原因取消，查看记录仍保留，换账号查询该资源重新可用。临近截止时不能绕过后端规则。
10. 改期选择其他空闲时段。抢走新时段或使版本失效后确认，原预约仍有效；正常成功后，可从详情互查原预约与新预约。
11. 退出后受保护接口不可用。切换患者账号，列表、详情和本地待确认内容不出现另一账号的资料。
12. 以 320/375/414 宽度检查首页、选择器、键盘、长门诊名、长姓名、倒计时、详情和安全区域。真机检查网络、滚动和点击行为。

## 自动化验证的实际范围

`npm run test -w @andrew/miniprogram` 会先真实编译，再在 Node 中加载生成的原生 CommonJS 模块，检查 `app.json` 登记的 10 页产物/事件绑定、网络不确定写入持久化、同 key 重试、结果核对、跨账号隔离、401 与过敏多行输入等客户端逻辑。这是带模拟 `wx` API 的客户端单元测试，不是微信渲染或真实微信接口联调，不能替代上述人工步骤。

客户端测试包含页面缓存清理、旧账号资料回包丢弃、旧账号 401 不撤销新会话、旧账号写入回包不清除新账号占位、价格整数分格式、资料只关联咨询、医生深链与只读演示标识等回归。实际执行项目数、通过/失败数及产物哈希，以最新的 `qa/client-unit.json`、`qa/client-unit.tap` 为准；本文不维护另一份静态测试计数。

另有使用**生成的原生模块连接真实 HTTP / PostgreSQL**的 smoke，脚本 `scripts/native-api-smoke.mjs`。先启动专门的本地测试服务，再运行：

```powershell
$env:MINIPROGRAM_SMOKE_API='http://127.0.0.1:3310/api/v1'
$env:MINIPROGRAM_SMOKE_ALLOW_CREATE='1'
node miniprogram/scripts/native-api-smoke.mjs
```

从仓库根目录执行上述命令。脚本会新建随机 `MP-SMOKE-*` 门诊、医生、资格、服务、牙椅、班次与两个合成患者，验证同资源竞争、提交后丢响应/同 key 恢复、取消释放、改期失败回滚及新旧关联。成功后撤销合成班次、停用资源，保留可追溯历史；不要在真实业务数据库运行。最新证据为 `qa/native-api-smoke.json`，包含被测试编译产物的 SHA-256。该执行方式使用 Node 的 `wx.request` 适配器，没有启动微信开发者工具或真机。

页面按账号清空患者缓存，并在异步回包时再次核对账号；切换账号后不会把旧请求结果写入新账号表单。本人资料编辑页提供当前账号有效占位的“继续核对预约”，在修改联系方式后可回到确认流程。

端到端数据库并发、事务、权限和重启验证以新后端测试与根交付文档为准。未接入正式微信授权、合法域名、短信或真机的部分不标记为已验收。
