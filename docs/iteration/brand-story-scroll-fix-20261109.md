# Hero 到品牌故事的滚动修复

## 复现与原因

修复前在 2457×1192、1920×1080、1440×1000 和 390×844 的本机 Chrome 中复现了图片交叠位置。页面可以继续滚动，视频在可见时也能正常播放；问题出在叠层和动画的衔接。

1. 整个品牌章节固定向上挪了 112px，手机为 52px，并使用较高的层级。图片一直压在首屏上，章节的透明区域还挡住了右侧视频按钮。三个桌面尺寸的真实鼠标点击均被 `section#about` 截获。
2. 图片只有很小的视差，入场采用播放一次后保留终态的 CSS 动画，没有随滚动归位的过程。
3. 首屏部分文字的入场和退场同时控制透明度；服务区的通用入场与章节衔接也重复控制了透明度和位移。
4. 1440×720 的短屏中，图片压住了“继续了解”。服务首卡下移 36px，超过列表底部的 18px 余量，使横向列表出现了 18px 的内部竖向溢出。

源码没有使用 GSAP 或 ScrollTrigger。修复针对实际的页面定位、样式控制和滚动调度。

## 修复内容

- 品牌章节恢复正常文档流。短暂交叠仅用于不可点击的图片层，入口位移随滚动归零。
- 图片入场根据首屏按钮和滚动提示的位置限幅，保留至少 16px 的间距。
- 图片揭幕直接裁切图片层，未显示的部分透出首屏，避免暖白遮罩在短屏上形成遮挡视频的矩形。
- 现有图片揭幕、文字显现、特点和服务衔接由同一个滚动调度计算；位置取自稳定的布局锚点，前进、停留和反向滚动都对应当前位置。
- 将首屏文字退场放在独立外层，保留内层原有入场效果和预约按钮。
- 服务标题和首卡由章节进度控制，避开通用入场；卡片位移限制在 16px，包括后加载的服务卡片，落在原有底部余量内。
- 组件离开后清理观察器、监听器和待执行帧。减少动态效果、无观察器和键盘阅读时直接显示完整内容。

保持原有文案、图片、链接、服务内容和 API。
