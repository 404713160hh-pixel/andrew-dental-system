# 患者小程序实现与验收

记录日期：2026-10-23（Asia/Shanghai）。当前工程为微信原生 TypeScript/WXML/WXSS，共10页；与 Vue 工作台共享 `/api/v1` 和 PostgreSQL。以下结果区分编译模块、真实 HTTP、微信渲染和真机。

## 1. 本轮完善内容

| 内容 | 已实现行为 |
| --- | --- |
| 首页 | 预约、门诊、医生团队、参考价格、本人预约和资料入口 |
| 医生列表与详情 | 按门诊浏览；简介、关注方向、资格示例、门诊及匹配咨询服务来自 API |
| 参考价格 | 24项资料，按类别/关键词筛选，显示年份、整数分换算的区间、单位、未核验来源及项目说明 |
| 预约衔接 | 医生详情保留医生预选；资料入口只关联咨询服务，自动定位提供该服务的开放门诊；失配时要求主动调整 |
| 虚构信息 | 6位虚构医生、8份虚构患者档案、6种检查/咨询服务；医生、本人资料、确认和预约记录均有明确标识 |
| 数据增量 | `db:demo` 开发专用，保留来源登记，重复执行无重复；不覆盖普通同名资料和旧预约，不复活已撤班次 |

治疗资料来自用户提供的2026年参考区间，逐项标注“用户提供的价格资料（未独立核验）”。它们不是门店报价。疗程价、按颗价和本次咨询预约费分别展示；参考价下限不会成为占位或预约费用。半口/全口起价和不封顶的舌侧费用没有改写成普通上下限。没有补入品牌疗效、报销或降价断言。

患者端没有患者名录，只能查看当前账号本人；其他演示档案供有权限的员工核对。`isDemo` 是只读标记，资料保存会剥除它；后端拒绝通过患者输入改写该字段。专业咨询同时要求基础资格和对应的模拟能力，不能仅靠前端筛选赋予资格。

## 2. 预约与账号保护

选择门诊/服务/日期/医生 → 服务端查询号源 → 有截止时间的短时占位 → 核对本人资料、联系方式、过敏声明与取消规则 → 正式确认。主诉不当作诊断；到诊、完成诊疗与预约状态分别处理。取消保留原因并释放资源；改期失败保留原约，成功保留新旧关联。

确认、取消、改期在发送前保存原键、路径、内容和所属账号。网络失败、5xx或不完整响应保留“结果待确认”；核对和重试使用同一键。`not_found` 不被解释为原请求永远不会提交。401后仍保留原账号命令，重新登录可继续核对。

账号切换清空旧表单、预约、详情和确认勾选。旧账号迟到的响应不能填入新账号页面、撤销新会话或清除新账号占位。选择占位前后也核对发起账号。

## 4. 下一步人工验收

1. 构建后在微信开发者工具手动导入 `miniprogram/`；配置中的小程序根目录为 `dist/`。手动导入不依赖 CLI 服务端口。
2. 若需要自动联调，在工具“设置→安全设置”开启“服务端口”，再运行本地自动化。
3. 检查10页的渲染、320/375/414宽度、长名称、键盘、滚动、安全区域及倒计时；用 `patient.a` 预约未来演示日期，完成改期、取消，并在前台核对同一预约。
4. 弱网和账号切换下核对结果未知、原键恢复和资料隔离。更换真实 AppID 后再验证预览及手机网络。
5. 正式部署配置 HTTPS、request 合法域名及证书，关闭演示登录；微信授权、通知、Docker/Nginx/TLS和真实业务资料分别验收。

当前 `touristappid` 和 `urlCheck:false` 仅供开发。手机的127.0.0.1指向手机自身；局域网和后端监听配置见[下一步操作](DEMO-NEXT-STEPS.md)及[小程序说明](../../miniprogram/README.md)。网页窄屏截图不是微信或真机证据。

设计 PDF 和旧 SQLite 业务代码没有修改。此前的实际数据库重启及 Compose 静态校验记录保留为各自日期的证据；本轮不将它们重述为新的生产部署验收。
