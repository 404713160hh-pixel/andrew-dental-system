## 2. 已实现的业务流程

首页展示由后端读取的门诊、项目和参考价格，提供预约、我的预约和个人资料入口。登录注册由后端认证，演示账号及开关从 `/auth/config` 动态取得，未声称完成微信授权登录。本人档案保持独立患者编号，联系电话可共用，过敏未知、声明无已知过敏、已知过敏分别处理。

预约流程为选择门诊/项目/日期/医生 → 服务器号源查询 → 短时占位 → 本人资料、联系方式、过敏与取消规则核对 → 正式确认。占位显示服务器截止时间，确认成功才显示预约编号。修改资料后，可在个人中心继续当前有效占位的核对流程。

我的预约仅查询本人列表与详情，支持分页、状态筛选、取消和改期。取消保留原记录与原因；改期先保留原预约，再选择其他空闲资源；新安排成功后可查询新旧关联。当前不提供与原有效预约重叠的改期号源。到诊和诊疗完成没有伪装为预约完成状态，也没有未实现的支付或病历入口。

## 3. 结果未知与账号隔离

确认、取消、改期在发送前持久保存 key、路径、原始内容与所属账号。网络失败、5xx 或不完整成功响应保留“结果待确认”；核对和重试继续使用原 key。服务端暂未找到命令不被解读为原请求永远不会提交。确定的校验失败后才允许修正并重新操作。

待确认命令和占位按账号分别保存，其他账号不可见且不会覆盖。401 保留原账号命令，重新登录后可继续核对。旧账号迟到的 401 不撤销当前新账号会话；旧账号迟到的成功结果不返回给新账号，也不会清除新账号占位。

最终自查还修复了页面缓存边界：账号切换时立即清空旧患者的表单、预约列表、详情和确认勾选；异步回包核对发起账号，防止旧请求将资料填入新账号页面。后端鉴权和客户端显示隔离分别验证。
