# 课程演示的下一步

微信开发者工具与网站的本地预约闭环已实测，当前结果见 `qa/cross-client.json`。下一步连接手机和部署环境；微信授权、真机和正式发布需分别验收。

## 1. 本地服务和数据准备

在 `andrew-system` 根目录操作。已经运行的终端继续使用，避免重复启动同一个数据库或 API。

```powershell
# 终端 1：保持运行；只监听本机 55432
npm run dev:postgres
```

```powershell
# 终端 2：只对课程开发库执行
npm run db:migrate
npm run db:seed
npm run db:demo
npm run dev:api
```

`db:seed` 建立原有合成初始数据；`db:demo` 增量补充本轮虚构医生、患者、咨询预约服务、参考价格和未来排班。执行后核对回执及重复运行结果，不清空旧数据，不在真实业务库执行。过期的演示班次不等于服务故障；应查看未来演示日期或由员工端发布新班次。

```powershell
# 终端 3：员工工作台，默认 http://127.0.0.1:5173
npm run dev:admin

# 另一个终端：只读检查新 API
Invoke-RestMethod http://127.0.0.1:3310/api/v1/health
```

健康结果应包含 `data.status: ok`、`data.database: postgresql`。运行状态会变化，演示前重新检查；连接失败时先核对数据库和 API 终端，不重复创建数据库或清空数据。

## 2. 导入微信开发者工具

```powershell
npm run typecheck -w @andrew/miniprogram
npm run build -w @andrew/miniprogram
npm run test -w @andrew/miniprogram
npm run sync:wechat
```

1. 本机使用已打开的 **`D:\AndrewDentalMiniProgram`**，同步脚本先备份源码、产物与配置，再同步源码和产物，保留 AppID 和工具配置；依赖安装与构建从仓库根执行。其他电脑可以导入仓库 **`miniprogram` 文件夹**，`miniprogramRoot` 为 `dist/`。
2. 当前沿用原工程的 AppID；其他开发者须使用自己有权限的测试/正式小程序 AppID。
3. 在“详情→本地设置”确认开发环境的域名、TLS、HTTPS 证书校验开关。当前本地项目 `urlCheck:false`，只适用于调试。
4. 模拟器 API 配置在 `miniprogram/src/config.ts`，本地地址为 `http://127.0.0.1:3310/api/v1`。改地址后重新 build，再点击工具“编译”。
5. 观察工具 Console/Network：门诊、虚构医生、参考价格和号源应来自真实 API。先检查后端连接，再处理白屏或页面错误。

`watch` 只监听 TypeScript；WXML、WXSS、JSON 或共享类型改变后执行完整 build。`npm start` 是旧版 SQLite 入口，本轮使用 `npm run dev:api`。

本机微信开发者工具为 **2.02.2609231 RC**，服务端口已按用户要求开启。官方 CLI 对 D 盘工程执行 `auto` 后，官方 SDK 驱动真实微信模拟器与 Chrome 员工网站完成发布、预约、改期、取消，并用同一 PostgreSQL 核对记录，证据见 `qa/cross-client.json`。

复测时先构建、同步，再通过官方 CLI 打开 D 盘工程的自动化端口。保持 API3310、Vue5173和 PostgreSQL55432运行后，设置 `$env:CROSS_CLIENT_ALLOW_FIXTURES='1'`，执行 `node scripts/booking-cross-client.mjs`。该脚本只允许本地开发库，建立独立合成资源并精确收尾。此次没有执行 preview、upload 或发布。

## 3. 价格与虚构人物的呈现边界

- 参考价格来源必须显示为 **“用户提供的价格资料（未独立核验）”**，`2026` 表示这份资料的参考年份，不代表系统核实了当年市场价或真实门诊收费。
- 保留原单位和区间：例如洁牙按次、补牙/牙冠/种植按颗、正畸按疗程。区间不能显示成单一固定价；“起价”不能变成全包价。
- 种植和正畸等项目只预约评估咨询。**预约咨询费与治疗参考费用分开**，不把参考价下限写入预约费。根管后牙冠另计、种植额外项目依面诊等条件应随参考资料展示。
- 对半口/全口下限、舌侧上限等有歧义的资料省略具体数值或说明歧义。医保、存留率、降价比例、名医等没有核验的信息不补写。
- 医生可以作为公开的虚构展示资料，姓名、简介和头像旁应能识别“课程演示/虚构”，不能伪造真实执业核验或真人背书。
- 虚构患者用于开发测试登录、本人资料和员工授权业务，不做小程序公开患者名录。明确只管理当前账号本人；真实姓名、联系电话、病史不要混入演示库。

## 4. 本地验收清单

| 验收动作 | 预期结果 |
| --- | --- |
| 查看参考价格，选择种植/正畸咨询 | 来源、单位、范围、额外费用条件可见；咨询预约费独立；无绑定咨询服务时没有无效预约按钮 |
| 查看虚构医生与演示登录 | 虚构标识明确；医生服务范围来自后端；登录候选不混入真实患者 |
| 员工新增未来班次，小程序查询 | 同一门诊、项目、日期显示同一号源，不使用前端假数据 |
| 患者甲占位，患者乙竞争同一资源 | 最多一人取得有效资源；不显示另一患者信息 |
| 确认后故意断网，再打开“我的预约” | 提示结果待确认，保留原操作标识；核对或同 key 重试只有一笔预约 |
| 修改本人资料、过敏声明，再继续确认 | 未知/无已知/已知过敏不同；不把只读演示标识写回资料接口；有效占位仍可继续核对 |
| 取消或改期 | 原因和记录保留；取消释放号源；改期失败原预约有效，成功有新旧关联 |
| 退出甲账号、登录乙账号，弱网重复切换 | 无旧表单、旧预约或迟到回包泄露；乙的占位不被甲的回包清除 |
| 320/375/414 宽度及长文案 | 来源、价格单位、时段、键盘、错误、倒计时与底部安全区域可读可操作 |

现有测试包括编译后的原生模块单元测试，以及原生模块经 `wx.request` 适配器连接真实 HTTP/PostgreSQL 的 smoke。读取 `miniprogram/qa/client-unit.json` 与 `miniprogram/qa/native-api-smoke.json` 的当次状态、执行时间和产物哈希，核对它们与当前 `dist` 一致，再报告通过数量。这些结果不等于微信开发者工具或真机已经测试。真实 API smoke 会创建独立命名空间的合成夹具，仅在专用开发库运行。

## 5. 手机与正式环境

手机调试时，`127.0.0.1` 指手机自己。先用 `ipconfig` 查电脑当前 Wi-Fi/网卡 IPv4；手机和电脑接同一局域网，将 `src/config.ts` 改为电脑 IP 的 3310 地址并重新 build。后端默认只监听本机，需由启动者把 `BOOKING_HOST` 改为该局域网地址或开发监听地址，并仅允许可信局域网访问 API 端口；PostgreSQL 继续只监听本机。不要只改手机端地址就认定后端可达。

真实 AppID 下按工具能力进行“真机调试/预览”，另行检查调试开关与网络可达性。开发跳过域名校验不构成正式上线条件。微信的网络与合法域名要求可参阅[微信小程序网络文档](https://developers.weixin.qq.com/miniprogram/dev/framework/ability/network.html)。

部署时采用目标服务器的 PostgreSQL、API、Nginx、持久卷和环境变量；先备份，再迁移。配置有效 HTTPS 证书、域名及微信 request 合法域名，恢复域名/证书校验并重建小程序。正式环境默认关闭演示登录，不把虚构演示患者作为真实业务患者，也不把课程参考价格直接当作正式收费表。是否接入微信授权、通知及其他外部能力，按真实凭据和联调结果分别记录。

微信模拟器闭环通过不代表手机、公网域名或微信授权已经通过；这些结果完成后分别补充记录。
