# 员工资料与季度激励对照验收

本轮按原始安德鲁案例补齐医生季度业绩和10%激励基金。用户于2026-11-06确认只补这一范围。原文未规定全员基本工资、税费和社保算法。

## 依据与对应关系

原始案例第1页要求记录牙医员工编号、姓名、出生日期、家庭住址、电话和邮箱，并定义净利润及10%激励基金；第2页要求逐季度跟踪每位牙医收入、医疗用品成本及运营费用。个人分配、亏损参与合计、独立复核和发放状态采用设计文档的补充制度。

| 业务要求 | 网站及接口 | 数据库与设计模型 |
| --- | --- | --- |
| 稳定员工身份及完整联系资料 | 员工档案与账号关联；医生管理补出生日期、家庭住址和邮箱；私人资料仅总部可读 | `staff`15字段、`users`8字段、`role_assignments`4字段；UC-02、UC-24及员工关系图 |
| 三类财务金额有账证 | 薪酬与激励的月度底稿；三类金额各附来源；负数更正保留依据 | `incentive_months`、`doctor_financial_sources`；UC-19、BP09 |
| 缺失不按零核算 | 全部门诊三个自然月逐项检查，零业务明确确认；已发布出诊医生必须有明细 | UC-20及关闭/重开内部序列、月度ER |
| 按医生跨店计算 | 先跨店合并，再合计包括亏损的全体净利润，正部×10%四舍五入到分 | `incentive_pools`、`incentive_pool_sources`、`doctor_quarter_results`；UC-21、BP10、基金ER |
| 分配守恒 | 按跨店正净贡献权重，最大余数法分配，稳定处理同余 | `incentive_allocations`；基金、份额类图和状态模型 |
| 制表和批准独立 | 不同有效账号及不同员工ID；未批准错误快照作废后重算；批准来源锁定 | UC-22及审批内部序列；快照和来源版本 |
| 发放可追溯且不超额 | 先登记待确认，再按凭据登记成功或失败；员工查询本人获批份额及付款 | `incentive_payments`；发放内部序列、ER、数据库额度触发器 |

季度财务输入使用已核对账证的医生月度汇总。预约报价、预约数量、预收款不会自动变成收入。系统登记核实后的激励付款结果，不调用银行代发。

## 本轮验证

- PostgreSQL/API全量测试88/88通过，包含既有预约从旧7次迁移升级后的保留、医生私人字段及未来预约保护、员工身份、制审隔离、完整月份、跨店亏损、分币尾差和并发发放额度。
- 网站测试59/59、小程序编译模块及模拟wx测试50/50通过；三端类型检查、API及网站生产构建、小程序正式HTTPS构建通过。
- 真实Chrome核验总部、店长、医生、前台的1440和390宽度页面，无页面脚本错误或横向溢出。实际页面执行草稿保存、6个月份的独立关闭、季度生成提交、另一总部人员批准、登记待确认发放和成功结果，医生本人看到同一份额和付款。
- 合成样本：全季度净利润22500元，基金2250元；三名医生跨店净贡献分别为18000、7500、-3000元，份额1588.24、661.76、0元。第一名登记成功500元后可发余额1088.24元。
- `scripts/verify-compensation-model.mjs`将当前PostgreSQL与设计模型逐项对照：员工身份及季度激励10张表124字段的字段集合、类型、空值、主键和外键一致；每个字段在TeX字典出现一次。模块7张激励表合计97字段。
- PDF采用中南大学版式，原位更新UC-19～UC-22、相关业务序列、内部序列、类图、状态及ER，保留24个系统用例。全页渲染、文本边界、引用及版式检查以[设计交付清单](../design/delivery-manifest.json)和[本轮结构化证据](qa/compensation-alignment-20261106.json)为准。

截图和完整本地日志在忽略目录 `.booking-data/compensation-e2e-20261105/`、`.booking-data/compensation-frontend-20261105/` 及本轮PDF检查目录。验证使用独立的本地合成数据库；没有修改公网财务数据，没有把模拟器检查记作手机真机验收。

## 更新部署

先备份现有PostgreSQL，使用迁移账号执行新增`008_staff_compensation.sql`，随后重新执行`deploy/booking/provision-runtime.sql`为新表授予运行账号权限，再更新API和Web镜像。原迁移校验和保持不变，既有医生、患者及预约不被重建。旧员工未知私人字段保留null，待核实后填写。

总部先在员工档案页关联本人及复核人员的独立员工身份，再登记、复核真实账证。月份缺项会阻止生成季度快照。本轮代码和文档已在本地验证；公网本轮模块的部署另以服务器实际迁移和镜像运行记录为准。
