# 预约闭环集成测试

## 当前记录

测试文件：`booking-api/test/booking.integration.test.ts`。

这份文件描述测试设计与执行方式。下方已记录实际执行结果：**30 项通过，0 项失败、跳过或取消**。未运行或受外部条件限制的项目不记为通过。测试直接运行 PostgreSQL 迁移及合成 seed，再调用真实 Fastify 路由和真实 Repository；不模拟 SQL 返回值，不用静态 Mock 代替预约成功。

## 数据隔离与命令

在仓库根目录执行：

```powershell
npm run test:booking
```

先保证 PostgreSQL 已启动。连接优先读取 `TEST_DATABASE_URL`，否则读取 `.env.booking` 的 `DATABASE_URL`。连接值只用于找到 PostgreSQL 服务器及认证，测试将管理连接指向 `postgres`，创建随机数据库 `andrew_test_<20位十六进制>`，绝不清空开发数据库。测试进程需要创建/删除自建数据库权限，普通生产业务账号不应承担这项测试职责。

每次测试运行都在新库上执行版本化迁移，并生成随机课程测试密码传给 seed。测试不会将密码写入仓库或日志。结束时先关闭应用和连接池，再仅终止该自建库连接并删除该库；删除前再次严格验证名称前缀及随机格式。若进程被强制终止，只能在确认确为测试库后手动清理残留，不能按宽泛目录或名称删除。

测试不启动 HTTP 监听端口，使用 `fastify.inject` 经过真实路由、认证、服务、事务及 PostgreSQL。浏览器 CORS、Nginx、TLS、微信开发者工具及真机能力需要另行验证。

| 改期末尾失败回滚 | 有效目标 hold 后停用目标资源，原约不变；另由测试触发器明确确认旧约已经改状态、旧资源已释放，再抛数据库异常，验证旧约、旧资源、目标 hold、事件、审计及回执全部回滚 | PostgreSQL 故障注入、事务 |
| 取消规则快照 | 以两小时规则建 hold，换七天规则服务确认及读取仍保持两小时；反向验证新七天预约不能借旧两小时默认值绕过 | 两个真实应用实例、持久快照 |
| 回执当前权限 | 前台代约后撤销门诊授权，重放原幂等命令和读取该回执均拒绝 | 当前 principal、API |
| 资格并发变更 | 一个真实 PostgreSQL 事务持有资格修改锁，确认请求出现 `pg_stat_activity` 可见的共享锁等待；停用提交后确认重新校验并拒绝 | 实际行锁及并发事务 |

直接 SQL 的测试变更只在独立测试库中造资格缺口、停用区间、到期边界与约束冲突，不修改生产/开发业务数据。它们用于检验数据库的最后防线，不替代 API 鉴权测试。故障注入触发器在测试库创建并于 `finally` 删除；它真正检查了事务中间状态，再抛出 PostgreSQL `23514`，因此证明的是旧资源释放后的整体回滚，而非仅在事务开始前拒绝无效 hold。

并发资格测试不凭固定延时认定加锁成功：它轮询当前测试库的 `pg_stat_activity`，观察 `FOR SHARE OF q` 的实际 `Lock` 等待，再提交资格停用并检查确认结果。

审阅及本轮回归促成两项后端修复：

1. 原幂等回执和命令恢复接口只按账号隔离，命中后没有再检查当前门诊权限。现重放与读取结果均按当前 principal 校验预约范围；新增撤销前台授权后的否定测试已通过。
2. 原最终确认、占位与排班发布读取资格目录时没有锁住资格行，可能与资格停用事务交错。现按稳定 ID 取得所需资格的共享锁再计算；新增真实锁等待及停用提交后的复核测试已通过。

本轮没有据此声称微信开发者工具、真机、正式微信授权、生产 HTTPS、容量目标或备份恢复目标已验收。浏览器及原生模块 HTTP 联调由对应记录单独报告，不并入这 30 项。

最终增加跨午夜号源回归：当天开始的服务即使次日结束，只要完整占用仍在班次内即可；按北京时间开始日期查询，不在午夜截断服务。最新版实际30/30通过。
