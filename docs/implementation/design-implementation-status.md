# 设计与开发现状核对

核对日期：2026-10-27。设计依据为 [系统设计文档 PDF](../design/安德鲁牙科系统设计文档.pdf)，共 300 个 PDF 页面；文中页码指 PDF 阅读器页码。代码依据为 `booking-api/`、`admin-web/`、`miniprogram/`、`shared/` 和 `database/migrations/`。此表记录开发现状，不改变设计文档的业务基线；设计目标和实际实现的模型、操作与接口并非一一等同。

| 设计内容及位置 | 当前实现 | 差异、后续工作 |
| --- | --- | --- |
| UC-01 患者信息（PDF 49–50） | 患者账号注册与登录、本人资料及过敏自述；前台按完整姓名或电话查询及建档。 | 本人功能是子集；监护人代办授权、疑似重复档案人工核对流程、医生临床复核未完成。过敏自述不等于临床核实。 |
| UC-02 医生及资格（PDF 51–52） | 授权员工维护医生及资格，记录有效期；患者可浏览医生信息，排班与号源由服务端验证资格。 | 展示资料和合成资格不是执业资质核验；真实上线须由机构核验。 |

| UC-05 查询号源（PDF 57–58） | 两端经同一 API 查询 PostgreSQL；按门诊、项目、日期、医生计算，考虑班次、牙椅、缓冲、有效预约与占位。 | 日期窗口由 `GET /booking-policy` 返回；号源展示不代表最终锁定。 |

用户端增加了日历、七日快选和分时段号源；员工端增加日期导航、医生分组日程、本人视角、排班卡片和移动端布局。采用的参考和证据见[界面改进记录](reference-ui-20261025.md)。这些是已开发的交互细节，并不改变后端统一校验与数据范围的职责。

## 已验证与未验证

截至 2026-10-25 的本地记录：[汇总](qa/reference-validation.json)列出 API 47、网站逻辑 41、小程序逻辑 34 项通过；真实微信开发者工具渲染检查 9 项、微信模拟器与浏览器跨端链路 15 项、医生浏览器视图 11 项、员工浏览器 12 项通过。跨端流程及同一预约记录的检查见[跨端证据](qa/cross-client.json)。这些是指定时间和环境下的验证，不是线上运行或真机验证。

当前 `POST /auth/wechat` 返回 501，微信身份登录尚未实现；小程序当前使用后端账号会话。Docker、HTTPS、真实设备、微信合法域名、正式数据、容量与备份恢复在目标环境仍需验证。UC-08～UC-23 涉及的提醒与候补、到诊、临床、结算及经营等业务没有随预约闭环整体交付；支付、退款、诊疗病历、到诊、药品库存、财务和正式通知不属于新预约系统已交付范围。旧 SQLite 程序独立保留，不能将旧系统功能算作新后端已具备。

接口事实以[API 契约](api.md)和当前代码为准，具体部署准备见[部署说明](deployment.md)。设计审查保留 2026-10-22 当时的分析及拟定方案，不作为当前实现证明。
